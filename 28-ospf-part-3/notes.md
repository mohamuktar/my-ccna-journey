# OSPF Part 3 — Short Revision Notes

## 1. Loopback Interfaces

* **Loopback = virtual interface**
* Normally always **up/up** unless manually shut down.
* Not dependent on a physical interface.
* Provides a **stable IP address** to identify/reach a router.
* Commonly used for **OSPF Router ID**.

```cisco
interface loopback 0
ip address 1.1.1.1 255.255.255.255
```

---

# 2. OSPF Network Types

### Broadcast

* Default on **Ethernet**.
* Neighbors dynamically discovered with Hello messages.
* Uses **224.0.0.5** → all OSPF routers.
* **DR + BDR election** occurs.
* Other routers become **DROthers**.

### Point-to-Point

* Default on **PPP/HDLC serial interfaces**.
* Neighbors dynamically discovered with **224.0.0.5**.
* **No DR/BDR election**.
* The two routers form a **Full adjacency directly**.

### Non-Broadcast

* Default on old technologies such as Frame Relay/X.25.
* Neighbors must be manually configured.
* Not a major CCNA focus.

| Network Type       | Default Example | DR/BDR? | Hello  |
| ------------------ | --------------- | ------- | ------ |
| **Broadcast**      | Ethernet        | ✅ Yes   | 10 sec |
| **Point-to-Point** | PPP/HDLC        | ❌ No    | 10 sec |
| Non-Broadcast      | Frame Relay     | ✅       | 30 sec |

**Dead timer:** 40 sec for Broadcast & Point-to-Point.

---

# 3. Broadcast — DR/BDR

### Election order

1. Highest **OSPF interface priority**
2. If tied → highest **Router ID**

Default priority = **1**

```cisco
interface g0/0
ip ospf priority 255
```

* Priority range: **0–255**
* Priority **0 = cannot become DR/BDR**
* DR/BDR election is **non-preemptive**.

  * Changing priority does **not** immediately replace the current DR.
  * Election occurs when OSPF is reset or the DR/BDR fails.

### DR failure

**BDR immediately becomes DR**, then a new BDR election occurs.

### DROthers

* DROthers form **Full adjacency with DR/BDR**.
* DROthers remain **2-Way with other DROthers**.
* This reduces unnecessary LSA flooding.

### Multicast

* **224.0.0.5** → All OSPF routers
* **224.0.0.6** → DR/BDR

**Memory trick:**

> `.5 = all OSPF routers`
> `.6 = DR/BDR`

# 4. OSPF Neighbor Requirements

For OSPF neighbors/adjacencies to work:

1. **Same area**
2. Interfaces in the **same subnet**
3. OSPF process is not shutdown
4. **Unique Router IDs**
5. **Hello timers match**
6. **Dead timers match**
7. Authentication settings match
8. **IP MTU matches**
9. **OSPF network type matches**

### Important troubleshooting

If stuck at **EXSTART** → check **MTU**.

If neighbors show **FULL** but routes aren't appearing → check **network type**, among other things.

### Useful commands

```cisco
show ip ospf neighbor
show ip ospf interface
show ip ospf interface brief
```

---

# 5. OSPF Timers

Default Broadcast / Point-to-Point:

* **Hello = 10 seconds**
* **Dead = 40 seconds**

Configure:

```cisco
interface g0/0
ip ospf hello-interval 5
ip ospf dead-interval 20
```

Both sides must match.

---

# 6. OSPF Authentication

Configure password:

```cisco
ip ospf authentication-key jeremy
```

Enable authentication:

```cisco
ip ospf authentication
```

Authentication settings must **match between neighbors**.

---

# 7. MTU

* Default IP MTU is usually **1500 bytes**.
* MTU mismatch may allow routers to become neighbors but prevent them from reaching **Full**.
* Often causes OSPF to get stuck in **EXSTART**.

```cisco
ip mtu 1400
```

---

# 8. Manually Change OSPF Network Type

```cisco
interface g0/0
ip ospf network point-to-point
```

Useful when a connection is physically Ethernet but logically only **two OSPF routers** are connected and you don't need DR/BDR.

# 9. Serial Basics

### DCE vs DTE

* **DCE** → provides clocking
* **DTE** → receives clocking

Find which side:

```cisco
show controllers s2/0
```

Configure clock on DCE:

```cisco
clock rate 64000
```

### Encapsulation

Default Cisco serial encapsulation:

**HDLC**

Change to PPP:

```cisco
encapsulation ppp
```

Both ends must use the **same encapsulation**.

# 10. OSPF LSA Types — CCNA

Only remember these 3:

| Type  | Name            | Purpose                                          |
| ----- | --------------- | ------------------------------------------------ |
| **1** | Router LSA      | Generated by every OSPF router                   |
| **2** | Network LSA     | Generated by the **DR** on multi-access networks |
| **5** | AS-External LSA | Generated by an **ASBR** for external routes     |

### Easy memory

**1 = Router**
**2 = Network/DR**
**5 = External/ASBR**

View LSDB:

```cisco
show ip ospf database
```

# 🔥 CCNA Must-Know

Memorize these:

* **Broadcast → Ethernet → DR/BDR**
* **Point-to-Point → no DR/BDR**
* **224.0.0.5 → all OSPF routers**
* **224.0.0.6 → DR/BDR**
* Highest **priority**, then highest **Router ID** → DR
* **Priority 0 = cannot be DR/BDR**
* DR election is **non-preemptive**
* **DROther ↔ DROther = 2-Way**
* **DROther ↔ DR/BDR = Full**
* Same **area/subnet**
* Matching **Hello/Dead timers**
* Matching **authentication**
* Matching **MTU**
* Matching **network type**
* **MTU mismatch → often EXSTART**
* LSA **1 = Router, 2 = Network, 5 = AS-External**
